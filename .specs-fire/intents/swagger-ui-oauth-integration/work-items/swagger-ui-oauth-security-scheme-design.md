# Design: OpenAPI OAuth2 authorization code scheme and Swagger UI settings

## Summary

When `ApiScopesConfiguration:BypassApiScopesAuthorization` is `false`, the OpenAPI document declares an OAuth2 `authorizationCode` security scheme and Swagger UI is configured with the client id, client secret and PKCE so the Authorize dialog lets the user pick scopes and complete the flow against the configured authority. When bypass is `true`, no security is added.

## Scope

**In Scope:**
- OAuth2 scheme and global security requirement in the NSwag document
- `OAuth2Client` settings in Swagger UI (client id, secret, PKCE)
- Startup validation that Swagger scopes are a subset of `AdminApiScopeName` / `ReaderApiScopeName`

**Out of Scope:**
- Tests (work item `swagger-ui-oauth-tests`)
- Changes to API authorization policies or JWT validation
- Optional override keys for authorize/token URLs
- OIDC discovery at startup

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Activation | `BypassApiScopesAuthorization == false` | Same single switch as `AddApiSecurity`. |
| Options access | `AddOpenApiDocument((config, sp) => ...)` reading `IOptions<>` | Avoids reading configuration twice. |
| Authorize / token URLs | `Authority` + `/connect/authorize` and `/connect/token` | IdentityServer/Duende convention; no I/O at startup. Approved by user. |
| Scheme scopes | Those in `SwaggerUITargetApiScopes` (name + title) | Agreed contract. |
| Security requirement | Global, no mandatory scopes per operation | Every endpoint accepts Reader or Admin; user picks scopes in the dialog. |
| Swagger UI client | `OAuth2Client` with ClientId, ClientSecret and PKCE enabled | PKCE protects the code even though the secret reaches the browser. Approved by user. |
| Bypass mode | No scheme, no `OAuth2Client` | Success criterion. |

## Technical Approach

### Architecture

```
appsettings -> SwaggerUIApiClientOptions  \
               AuthorityConfiguration      > AddWebApiConfiguration (OAuth2 scheme in document)
               ApiScopesConfiguration     /
                                           > UseSwaggerUiIfConfigured (OAuth2Client: id, secret, PKCE)
Browser -> /swagger -> {Authority}/connect/authorize -> {origin}/swagger/oauth2-redirect.html
        -> {Authority}/connect/token -> Bearer token -> API
```

## Security Considerations

- **Client secret in browser**: Swagger UI exposes it to the client; use only in Local/Dev, never commit it (user-secrets / environment variables).
- **Redirect URI**: `{origin}/swagger/oauth2-redirect.html` must be registered at the authority.
- **Scope alignment**: Swagger scopes must be a subset of the API's Admin/Reader scopes, validated at startup.

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Secret reaches the browser | High | Document; Local/Dev only; never in `appsettings.json`. |
| Authority endpoints are not `/connect/*` | Medium | Documented limitation; override keys can be added later. |
| Redirect URI not registered at authority | Medium | Document in walkthrough. |
| Authority rejects PKCE with a confidential client | Low | Document; PKCE can be disabled by a follow-up change. |
| Swagger scopes drift from API scopes | Low | Startup validation. |
